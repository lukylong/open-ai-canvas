# 后端数据库

后端通过 GORM 管理 SQLite 与 PostgreSQL 表结构。服务启动时由 `backend/internal/database/schema.go` 执行迁移；业务写路径必须通过 service 和 repository 的状态约束，不能直接依赖前端状态。

## ComfyUI Bridge

| 表 | 用途 | 关键边界 |
| --- | --- | --- |
| `comfy_bridges` | 保存用户注册的 Bridge 身份、Token 摘要、启用状态和心跳能力 | Token 明文只在注册时返回一次；查询和日志只使用摘要 |
| `comfy_bridge_requests` | 保存云端任务交给本地 Bridge 的请求、领取状态和完成结果 | `id` 同时作为任务的 `provider_request_id`；状态按 `queued -> claimed -> succeeded/failed/cancelled` 单向流转 |

`comfy_bridge_requests` 是 Bridge 交接的真相源。后端进程重启后，未领取请求继续从数据库投递；已领取请求的迟到结果先落库，任务 worker 恢复后使用原请求 ID 读取结果，不会创建第二次本地工作流执行。请求有效期当前为两小时，过期的排队或执行记录会转为失败。

请求表保存工作流执行 payload 和结果，但不保存 Bridge Token。任务取消时，未领取请求可以确定取消；已经领取的本机工作流无法可靠中止，迟到结果会被丢弃并进入费用核对流程。

## ZQ 能力迁移与批量分发

- `users.avatar_url`、`users.source_system` 保留迁移头像与来源；`invitation_codes` 和 `invitation_code_usages` 保存邀请码及一次性使用记录。
- `resources.source_system`、`resources.deletion_policy` 将迁移资源标记为 `zq-media-studio` 与 `retain_shared`；删除时只清理影策引用，不删除共用 COS 对象。
- `migration_runs`、`migration_entity_maps`、`migration_conflicts` 保存增量 watermark、稳定 ID 映射、校验和及人工冲突；增量读取使用重叠窗口并依赖唯一映射幂等。
- `distribution_publications` 与 `distribution_outboxes` 原子创建，保存发布快照、幂等键、重试和终态。
- `director_prompt_proposals` 保存导演候选及用户选择，只有已选择且未消费的 proposal 才能创建 storyboard session。
- `task_batches`、`task_batch_items` 与 `tasks.batch_id/batch_item_id/batch_index` 保存最多 1000 项的持久批次；等待项不占活动任务并发，调度时仍经过现有路由、计费和 Worker 租约。

注册时邀请码计数、用户和 usage 位于同一事务；修改密码同时撤销该用户全部会话。批次请求只保存逻辑模型路由清理后的参数，不持久化浏览器提交的渠道地址、Header 或密钥。
